## 1. Git — o que é, versão, instalação
- git-scm.com/about: sistema de controle de versão distribuído, livre e de código aberto sob a GPLv2; «96% dos desenvolvedores profissionais usam Git» (pesquisa citada no site, 2022); histórico do kernel Linux (1,4 milhão de commits) ocupa 5,5 GB.
- Versão mais recente: **Git 2.55.0** (git-scm.com/install em 09/09/2026; tag `v2.55.0` no github.com/git/git). Instalação: git-scm.com/install (Windows: instalador «Git for Windows»; macOS: Homebrew `brew install git` ou Xcode Command Line Tools; Linux: `apt install git`, `dnf install git`). Nesta máquina: Git 2.48.1.
- Livro oficial *Pro Git*, 2ª ed. (Scott Chacon e Ben Straub, Apress, 2014), tradução para português **completa** em git-scm.com/book/pt-br/v2, licença CC BY-NC-SA 3.0, PDF/EPUB gratuitos; capítulos: Primeiros Passos, Fundamentos do Git, Ramificação, Git no Servidor, Git Distribuído, GitHub, Ferramentas do Git, Customizando o Git, Git e Outros Sistemas, Git Internals, apêndices (Git em outros ambientes, incorporando o Git, comandos).
- Configuração inicial: `git config --global user.name "…"` e `git config --global user.email "…"` (o VS Code exige isso e Git ≥ 2.0.0). `git init -b main` cria o repositório com o branch `main` (saída real: «Repositório vazio Git inicializado em …/.git/» em Git em português).
- Comandos usados de verdade na demonstração (figuras gh_t1, gh_t2): `git status --short` (`??` = não rastreado), `git add <arquivos>`, `git commit -m "…"` (saída: `[main (root-commit) 3b95655] …  4 files changed, 25 insertions(+)`), `git log --oneline`, `git switch -c <branch>`, `git diff` (linhas `-`/`+`), `git commit -am`, `git switch main`, `git merge <branch>` (saída «Fast-forward»), `git tag -a v0.1-qualificacao -m "…"`, `git log --oneline --graph --decorate` (mostra `HEAD -> main, tag: v0.1-qualificacao`), `git remote add origin <url>`, `git push -u origin main --follow-tags` (saída `* [new branch] main -> main`, `* [new tag] …`), `git rm --cached <arquivo>` (tira do Git sem apagar do disco).
- `.gitignore` (docs.github.com «Ignorar arquivos»): fica na raiz; modelos oficiais em github.com/github/gitignore (há `TeX.gitignore`, `Python.gitignore`, `R.gitignore`); gerador gitignore.io; ignorar em todos os repositórios da máquina: arquivo `~/.config/git/ignore`; arquivo já rastreado só sai com `git rm --cached ARQUIVO` e depois a regra no `.gitignore`.
- Git LFS (git-lfs.com): «substitui arquivos grandes como amostras de áudio, vídeos, conjuntos de dados e gráficos por ponteiros de texto dentro do Git, guardando o conteúdo num servidor remoto»; versão **v3.8.0** (release de 28/08/2026); `git lfs install` (uma vez), `git lfs track "*.psd"`, `git add .gitattributes`, depois commit e push normais; Windows instalador, macOS `brew install git-lfs`, Linux PackageCloud/tarball. Nesta máquina o LFS não está instalado (`git: 'lfs' não é um comando git`).

## 2. GitHub — planos, limites, recursos (docs.github.com/pt e github.com/pricing, 09/09/2026)
- **GitHub Free** (contas pessoais): repositórios públicos e privados ilimitados, colaboradores ilimitados, 2.000 minutos de GitHub Actions por mês, 500 MB de armazenamento no Packages, 120 horas-núcleo e 15 GB de Codespaces por mês, GitHub Pages em repositórios públicos, alertas do Dependabot, suporte da comunidade. Preço: US$ 0.
- **Team**: US$ 4 por usuário/mês (github.com/pricing, «first 12 months»); 3.000 minutos de Actions, 2 GB de Packages, revisores obrigatórios, branches protegidas, code owners, suporte por e-mail/web. **Enterprise**: US$ 21 por usuário/mês; 50.000 minutos, 50 GB, SAML SSO, SLA 99,9%. GitHub Pro (individual) não aparece em destaque na página de preços; vem gratuito no Student Developer Pack.
- **Student Developer Pack** (education.github.com/pack): «GitHub Pro gratuito enquanto você for estudante», Copilot, «acesso Pro ao Codespaces» e mais de 50 ferramentas de parceiros; pedido em github.com/settings/education/benefits para «estudantes verificados» (a página não detalha os documentos; a verificação é feita pelo GitHub).
- **Limites de arquivo** (docs «Sobre arquivos grandes»): aviso acima de **50 MiB**; **bloqueio acima de 100 MiB**; upload pelo navegador até **25 MiB** por arquivo; repositório idealmente **< 1 GB**, «fortemente recomendado» **< 5 GB**. Arquivos acima disso pedem Git LFS.
- **Git LFS no GitHub** (docs de cobrança): Free e Pro incluem **10 GiB** de armazenamento e **10 GiB** de largura de banda; Team/Enterprise Cloud 250 GiB; o excedente é cobrado por GiB baixado e por hora de armazenamento (calculadora de preços).
- **Hello World** (docs/pt): «+» → «Novo repositório» → nome `hello-world`, descrição, Público/Privado, «Adicionar um arquivo LEIAME» → «Criar repositório»; branch: menu «main» → digitar `readme-edits` → «Criar branch: readme-edits a partir do main»; editar README → «Confirmar alterações» (mensagem de commit) → «Confirmar alterações»; «Solicitações de pull» → «New pull request» → «Criar solicitação de pull»; «Mesclar solicitação de pull» → «Confirmar mesclagem» → «Excluir ramo».
- **README** (docs): o GitHub lê README em `.github/`, na raiz ou em `docs/` (nessa ordem); deve dizer o que o projeto faz, por que é útil, como começar, onde obter ajuda, quem mantém; gera sumário automático; acima de 500 KiB é truncado; README num repositório com o nome do usuário aparece no perfil.
- **Releases** (docs): «Versões» → «Rascunho de uma nova versão» → «Escolher uma marca» (tag existente ou nova) → «Título da versão» → «Descrever esta versão» (ou «Gerar notas de lançamento») → anexos opcionais → «Este é um pré-lançamento» → «Definir como versão mais recente» → «Publicar versão» ou «Salvar rascunho»; toda release traz ZIP e tar.gz do código automaticamente.
- **CITATION.cff** (docs): arquivo na raiz, formato Citation File Format; campos básicos `cff-version`, `message`, `authors` (`family-names`, `given-names`), `title`, `version`; com ele o GitHub mostra o botão **«Cite this repository»** na barra lateral, com exportação **APA** e **BibTeX**; `preferred-citation` aponta para o artigo quando se quer que citem o artigo e não o software. citation-file-format.github.io: versão **1.2.0**; ferramentas **cffinit** (formulário web) e **cff-converter-python** (`cffconvert`, para BibTeX, RIS, CodeMeta); lido por GitHub, Zenodo e Zotero.
- **DOI pelo Zenodo** (docs «Referenciar e citar conteúdo»): condições — repositório **público** e com **licença**; passos: zenodo.org → «Entrar com GitHub» → «Autorizar Zenodo» → página GitHub do Zenodo (zenodo.org/account/settings/github/) → alternar o repositório para «Ativado»; «o Zenodo arquiva seu repositório e emite um novo DOI sempre que você cria uma versão (release) do GitHub». help.zenodo.org («Enable a repository»): menu do perfil → GitHub → «Sync now» → ligar o controle deslizante → novas releases «são automaticamente ingeridas e arquivadas»; metadados por `CITATION.cff` ou `.zenodo.json`; integração com o Software Heritage.
- **GitHub Pages** (docs): hospedagem de site estático a partir do repositório; site de usuário no repositório `<owner>.github.io` (URL `https://<owner>.github.io`, um por conta); site de projeto em `https://<owner>.github.io/<repo>`; domínio próprio opcional; limites: repositório recomendado ≤ 1 GB, site ≤ 1 GB, largura de banda **flexível de 100 GB/mês**, **10 builds/hora** (salvo Actions próprio); proibido uso comercial/e-commerce e envio de senhas ou cartões; IPs dos visitantes são registrados.
- **Codespaces**: «ambiente de desenvolvimento hospedado na nuvem», pelo navegador, VS Code ou CLI; cota gratuita mensal em contas pessoais (120 horas-núcleo, 15 GB — da página de planos).
- **Pull requests / issues** (docs): pull request propõe mudanças de um branch para outro com revisão e discussão; issues rastreiam tarefas, bugs e ideias no repositório.
- **GitHub Desktop** (github.com/apps/desktop; repo desktop/desktop): «Experience Git without the struggle»; cliente gráfico; código aberto sob **MIT**; release **3.6.5** (04/09/2026); a página não lista plataformas (o repositório distribui para Windows e macOS; Linux só por builds da comunidade — não afirmar no manual além de «Windows e macOS»).
- **GitHub CLI** (cli.github.com): «GitHub CLI brings GitHub to your terminal. Free and open source»; repos, issues, pull requests, releases, checks, aliases; `brew install gh`, WinGet, apt/dnf/zypper; versão **v2.100.0** (03/09/2026). Nesta máquina: gh 2.46.0.
- Repositório público usado nas capturas: github.com/joaopaulomirandamatias/revisao-sistematica-pesquisa-cientifica (repositório do manual de revisão sistemática desta série; página inicial, commits, Actions com o workflow `verificar.yml`, arquivo README, grafo de rede). Releases de exemplo: github.com/zotero/zotero/releases (projeto de terceiros).

## 3. Overleaf, OSF, GitLab e alternativas
- **Overleaf** (docs.overleaf.com «Git integration and GitHub synchronization»): ambos são **recursos premium** (Overleaf Cloud pago; Server Pro 4.0+ para Git). Git: em «Integrações»/Menu → Sync → Git; URL de clone `https://git.overleaf.com/<ID_DO_PROJETO>`; autenticação por **token** (criado nas configurações da conta); **não suporta branches, Git LFS, tags, submodules**; symlinks viram arquivos; o branch chama-se `main`. GitHub Synchronization: liga um projeto Overleaf a um repositório GitHub e mantém sincronizados (só Overleaf Cloud premium). No plano gratuito, a saída é «Download → Source» (zip) e versionar localmente.
- **OSF** (help.osf.io «Connect GitHub to a project»): projeto → «Add-ons» → «Additional Storage» → «Connect» em GitHub → nome da conta → «Authorize» → login no GitHub → «Authorize CenterForOpenScience»; escolhe-se **um repositório por projeto**; sincronização bidirecional dos arquivos na seção «Files»; **não faz backup** do conteúdo no OSF; limite de 100 MB por arquivo enviado do OSF para o GitHub.
- **GitLab** (about.gitlab.com/pricing em português, captura gh_35, 09/09/2026): plano **Gratuito** US$ 0 por usuário/mês, «Não é necessário cartão de crédito», «5 usuários por grupo de nível superior», «400 minutos de computação por mês», gerenciamento de código-fonte e CI/CD, «Armazenamento ajustável de 10 GiB»; **Premium** US$ 29 por usuário/mês cobrado anualmente; **Ultimate** (preço sob consulta na página). Alternativa ao GitHub com o mesmo Git por baixo.
- Outras plataformas citadas pelo The Turing Way: GitLab e Codeberg.

## 7. Scripts do manual (rodados de verdade em 09/09/2026, figuras gh_t3 e gh_t4)
- `checar_repo.py [pasta]` — só leitura: arquivos rastreados > 50 MiB (AVISO) e > 100 MiB (BLOQUEIO), nomes e conteúdos com cara de segredo (`.env`, `.pem`, `id_rsa`, tokens `ghp_`/`AKIA`/`sk-`, chave privada PEM), padrões de CPF e listas de e-mails em arquivos de texto (LGPD), pastas de dados brutos (`dados_FORA_DO_GIT/` etc.), binários > 5 MiB, falta de README/LICENSE/CITATION.cff/.gitignore, ausência de remoto, mudanças sem commit; sai com 1 se houver bloqueio. Na demonstração achou o `.env` adicionado à força (BLOQUEIO) e a falta de LICENSE e CITATION.cff.
- `salvar_versao.sh "mensagem" [--tag vX.Y "descrição"]` — `git add -A`, mostra o `--stat`, recusa arquivos > 100 MiB, faz o commit e a tag anotada, imprime o comando de push (`git push --follow-tags`) ou orienta a criar o remoto.
- `citacao_cff.py --titulo --autores "Sobrenome, Nome; …" --versao --data [--doi --url --licenca --orcid]` — grava `CITATION.cff` 1.2.0 (recusa sobrescrever sem `--forcar`), imprime a entrada BibTeX `@software` e a referência no padrão ABNT para conferir com a biblioteca.
- O plugin já inicializa o Git em `iniciar_projeto.py` (pasta `dados_FORA_DO_GIT/` fora do versionamento).
